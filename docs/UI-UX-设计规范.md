# MenuLens UI/UX 设计规范

> 配套文档：《MenuLens 产品需求文档 v1.0》
> 风格方向：温暖食欲感 · 版本 v1.0

---

## 一、设计理念

### 1.1 视觉定位

**一句话**：让AI 看起来像一个懂吃的朋友，而不是一个冷冰冰的机器。

食物类产品最容易犯的错是"设计感压过食欲"。我们的策略是：**用克制的界面托住放大的食物本身**。界面退到背景，菜品才是主角。

### 1.2 三条铁律

**① 食物优先**
任何一屏，第一眼必须是菜品/菜单/食物，而不是标题、按钮或文字。图片永远比文字大、比文字先被看到。

**② AI 有存在感，但不妨碍**
Agent 的思考过程要**可见**（这是建立信任的核心手段），但不能阻塞用户操作。用户永远能提前做下一步。

**③ 不确定要看得见**
置信度不是给工程师看的指标，是给用户做决策的信息。所以它必须以普通人能懂的方式呈现。

### 1.3 情绪基调

| 维度 | 避免 | 采用 |
|---|---|---|
| 温度 | 冷冰冰的科技蓝 | 暖橙 + 奶油白 |
| 密度 | 塞满信息 | 留白充足，信息分组 |
| 语气 | 命令式、术语化 | 像朋友说话，带点俏皮 |
| 反馈 | 静默、菊花转圈 | 有意义的进度 + 可解释 |

## 二、设计系统（Design Tokens）

### 2.1 色板

#### 品牌色
```
--brand-primary:        #FF6B35   /* 暖橙 · 主色 */
--brand-primary-hover:  #F0551F   /* 按下态 */
--brand-secondary:      #FFA94D   /* 辅助橙 */
--brand-gradient:       linear-gradient(135deg, #FF6B35, #FFA94D)
```

#### 背景与表面
```
--bg-primary:      #FFFBF7   /* 奶油白页面底 */
--bg-surface:      #FFFFFF   /* 卡片 */
--bg-elevated:     #FFF4EC   /* 强调表面/输入框 */
--bg-brand-soft:   #FFF0E8   /* 主色浅底（chips/标签）*/
```

#### 文字（暖黑，不用纯黑）
```
--text-primary:    #2B2118   /* 主文字 */
--text-secondary:  #7A6A5D   /* 次文字 */
--text-tertiary:   #A8998C   /* 三级/占位 */
--text-on-brand:   #FFFFFF   /* 主色上的文字 */
```

#### 语义色
```
--success:   #2FA84F   /* 高置信度 / 成功 */
--warning:   #F5A524   /* 中置信度 / 警告 */
--danger:    #E5484D   /* 低置信度 / 风险 / 过敏 */
--info:      #3B82F6   /* 提示（少用）*/
```

#### 分割与阴影
```
--divider:        #F0E6DC
--shadow-sm:      0 2px 8px rgba(43,33,24,.06)
--shadow-md:      0 6px 20px rgba(43,33,24,.10)
--shadow-lg:      0 12px 40px rgba(43,33,24,.14)
```

**使用比例**：奶油白背景 60% · 白卡片 25% · 暖橙强调 10% · 语义色 5%

### 2.2 字体系统

```
字体栈: "PingFang SC", -apple-system, BlinkMacSystemFont,
        "Helvetica Neue", "Microsoft YaHei", sans-serif
数字栈: 同上，数字使用 font-feature-settings: "tnum"（等宽数字）
```

| 层级 | 字号/行高 | 字重 | 字距 | 用途 |
|---|---|---|---|---|
| Display | 32 / 40 | 700 | -0.5 | 价格大数字、结果统计 |
| H1 | 24 / 32 | 700 | -0.3 | 页面标题 |
| H2 | 20 / 28 | 600 | -0.2 | 区块标题 |
| H3 | 17 / 26 | 600 | 0 | 菜名、卡片标题 |
| Body | 15 / 24 | 400 | 0 | 正文 |
| Body-S | 14 / 22 | 400 | 0 | 次要正文 |
| Caption | 13 / 20 | 400 | 0 | 辅助说明 |
| Micro | 11 / 16 | 500 | +0.2 | 标签、置信度徽标 |

**字号下限 11px，正文不低于 15px**（老人用户群可读性）。

### 2.3 间距系统

4 的倍数：`4 · 8 · 12 · 16 · 20 · 24 · 32 · 40 · 48 · 64`

页面左右安全边距统一 `20px`（小程序端 `rpx` 为 `40rpx`）。

### 2.4 圆角系统

| 名称 | 值 | 用途 |
|---|---|---|
| `radius-card` | 20px | 主卡片 |
| `radius-button` | 14px | 按钮 |
| `radius-input` | 14px | 输入框 |
| `radius-badge` | 8px | 徽标 |
| `radius-pill` | 999px | 胶囊/chip |
| `radius-sheet` | 24px（顶部）| 底部抽屉 |

### 2.5 阴影层级

```
L0  无阴影          → 页面背景元素
L1  --shadow-sm     → 常规卡片
L2  --shadow-md     → 浮起卡片、悬停态
L3  --shadow-lg     → 底部抽屉、模态框
```

### 2.6 图标风格

- 线性图标为主，线宽 **2px**（小尺寸 1.5px）
- 端点圆角 `stroke-linecap: round`
- 图标尺寸：16 / 20 / 24 / 32 / 48
- 遵循 emoji 使用：仅用于「主行动按钮」和「菜系标签」等轻松场景，不用于关键信息

## 三、组件规范

### 3.1 按钮

#### 主按钮（Primary）
```css
.btn-primary {
  height: 56px;
  background: var(--brand-gradient);
  color: #fff;
  border-radius: 14px;
  font-size: 17px;
  font-weight: 600;
  box-shadow: 0 6px 16px rgba(255,107,53,.28);
}
.btn-primary:active { transform: scale(.97); }
```

#### 悬浮主 CTA（首页 Hero）
- 高度 56px，圆角 16px
- 前置图标 24px
- 悬浮在 Hero 图底部，带 `margin: -28px 20px 0` 形成"探出"效果

#### 次按钮（Secondary）
```css
.btn-secondary {
  height: 48px;
  background: var(--bg-elevated);
  color: var(--text-primary);
  border-radius: 14px;
}
```

#### 幽灵按钮（Ghost）
- 无背景，仅文字 + 可选细边框
- 用于 `[纠错]` `[换一道]` `[重置]` 等轻操作

#### 禁用态
- `opacity: .4`，同时禁用点击
- **禁止**用灰色文字 + 无反馈的方式（用户会以为卡住）

### 3.2 菜品卡片（Dish Card）—— 核心组件

```
┌─────────────────────────────────────┐
│ [图] 白切鸡               ¥58  荤菜 │  ← 图 64x64 圆角 12px
│      Poached Chicken  ⬤⬤⬤⬤⬤ 92%   │
│      ────────────────────────────   │
│      文火浸熟，皮爽肉滑，配姜葱油     │
│      ────────────────────────────   │
│      清淡 ●○○○  微辣 ●○○○○         │  ← 口味点阵
│      ⚠ 过敏原 [蛋]        [纠错]     │
│      [🥘 这样做 →]                   │
└─────────────────────────────────────┘
```

**规格**：
- 卡片 padding 16px，圆角 20px，背景 `--bg-surface`
- 相邻卡片间距 12px
- 菜名 17px/600，原名与译名上下排列
- 价格 17px/600，`--text-primary`

**置信度三态**（严格遵守，不可简化）：

| 置信度 | 徽标样式 | 左侧边框 | 菜名 | 附加信息 |
|---|---|---|---|---|
| ≥ 0.8 | ⬤⬤⬤⬤⬤ 绿 · "92% 可信" | 无 | 正常 | 来源标签 |
| 0.5–0.8 | ⬤⬤⬤⬤○ 黄 · "78% 建议核对" | 3px 黄条 | 正常 | "⚠ 建议核对价格" |
| < 0.5 | ⬤⬤○○○ 红 · "41% 存疑" | 3px 红条 | "可能是 XX" | 候选列表按钮 |

**色盲友好**：置信度用「点阵数量 + 颜色 + 文字」三重编码，绝不只靠颜色。

**来源标签**（可展开）：
```
▸ 来源：视觉识别 + 知识库匹配
  视觉菜名置信度 0.91 · 知识库匹配 0.95 · OCR 命中
  [为什么是这个分数？]  ← 点击解释置信度算法
```

### 3.3 约束控件

#### 人数 Stepper
```
[－]  3 人  [＋]
```
- 减号按钮 40x40，圆角 12px，`--bg-elevated`
- 中间数字 20px/600，等宽数字（避免跳动）
- 边界禁用而非报错

#### 预算 Slider
```
¥[  200  ]
●━━━━━━━○──────────
0       500      5000
```
- 轨道 4px，`--divider`；已选段暖橙渐变
- 滑块 24px 白色圆 + 暖橙描边 + 阴影
- 上方数字可点击直接输入

#### 辣度 Segmented
```
┌──────┬──────┬──────┬──────┐
│ 不辣 │ 微辣 │ 中辣 │ 重辣 │
└──────┴──────┴──────┴──────┘
```
- 容器 `--bg-elevated`，圆角 14px，padding 4px
- 选中态：白色背景 + `--shadow-sm` + 暖橙文字

#### 忌口 Chips
```
[香菜 ✓] [海鲜 ✓] [辣] [花生] [牛肉]
```
- 多选，选中态 `--bg-brand-soft` 底 + 暖橙文字 + 暖橙边框
- 未选中：透明底 + 灰边框
- 已忌口项从菜单中硬过滤，被过滤时顶部显示"已为你排除 3 项含香菜菜品"

### 3.4 方案卡片（Plan Dish Card）

```
┌─────────────────────────────────────┐
│ 白切鸡                       ¥58    │
│ 粤式经典，皮爽肉滑，配姜葱油          │
│ 💡 招牌菜，配姜葱油解腻              │
│                      [换一道]        │
└─────────────────────────────────────┘
```
- 与菜品卡片区分：左侧无图（方案里图片意义不大），改为带 `role` 标签（主菜/素菜/汤）
- `💡` 理由行使用 `--bg-brand-soft` 浅橙底，圆角 12px，内边距 10px
- 理由 ≤ 2 行，超出省略

### 3.5 吸底操作栏（Sticky CTA）
```
┌─────────────────────────────────────┐
│ 已识别 24 项 · 3 项待确认      [ ? ] │
│ ┌─────────────────────────────────┐ │
│ │ 👥2人  ¥200  微辣  忌口2项       │ │
│ │         ✦ 生成点单方案         │ │
│ └─────────────────────────────────┘ │
└─────────────────────────────────────┘
```
- 高度自适应，双行
- 背景白色 + 顶部 1px `--divider` + `--shadow-lg`
- `padding-bottom` 加安全区

### 3.6 Agent 思考态（Trust Pattern）

```
┌─────────────────────────────────────┐
│ ✦ 正在为你搭配...              [1.8s]│
│ ✓ 已完成菜单识别（24 道菜）           │
│ ● 正在匹配菜品知识库...               │
│ ○ 正在按你的偏好搭配                   │
│ ○ 校验预算                            │
└─────────────────────────────────────┘
```

**规则**：
- **禁止**使用空转菊花/骨架屏代替
- 每步 1.5s 完成，逐条点亮：待处理 `○ 灰` → 进行中 `● 橙+呼吸光` → 完成 `✓ 绿`
- 步骤文案必须是真实的业务动作，不是假进度
- 点击任一步骤可展开细节（建立可解释性）

### 3.7 流式消息气泡

```
用户消息（右对齐）
┌───────────────┐
│     [图片]     │  浅灰底 #F2EDE7
└───────────────┘

AI 消息（左对齐）
┌─────────────────────────┐  白色底 + 左侧 3px 暖橙渐变条
│ 已识别 24 道菜，最贵的招牌  │
│ 是白切鸡 ¥58。             │
│ ┌─────────────────────┐ │
│ │ [菜品卡片内联]       │ │  整块淡入
│ └─────────────────────┘ │
│ ▸ 来源：视觉+知识库       │  ← 折叠的来源说明
└─────────────────────────┘
```
- 用户气泡最大宽度 65%，AI 气泡最大宽度 82%
- 内联卡片整块淡入 400ms，不逐字
- 来源行默认折叠，`▸` 可展开

### 3.8 快捷指令 Chips
```
[不吃香菜] [预算 300] [换一道] [要清淡点]
```
- 横向可滚动，隐藏滚动条
- 高度 32px，圆角 999px
- 用于降低输入成本 + 展示 Agent 能力边界

### 3.9 置信度说明弹层
点击置信度徽标触发：
```
╭──────────────────────────────╮
│  这个 92% 是怎么来的？          │
│                               │
│  菜名识别    ▓▓▓▓▓▓▓▓░░ 0.91 │
│  知识库匹配  ▓▓▓▓▓▓▓▓▓▓ 0.95 │
│  OCR 文本命中 +0.15            │
│  ─────────────────────────── │
│  综合置信度          0.92      │
│                               │
│  📎 规则：单菜置信度 =          │
│  视觉×0.6 + 知识库×0.3 +       │
│  OCR 加成×0.1                 │
╰──────────────────────────────╯
```
这是差异化功能，也是把"AI 黑箱"变成"可理解系统"的关键。

## 四、信息架构

### 4.1 导航结构

```
小程序底部 Tab（4 个）
┌─────────┬─────────┬─────────┬─────────┐
│ 🏠 首页  │ 📷 识菜  │ 📖 菜谱  │ 👤 我的  │
└─────────┴─────────┴─────────┴─────────┘
     ↑          ↑         ↑
  主入口    核心功能   延伸功能
```

**非 Tab 全屏页**：菜单结果页、方案页、菜谱详情页、历史页、设置页

**全局浮层**：AI 助手抽屉、约束配置面板、菜品详情弹层、置信度说明

### 4.2 全局常驻元素

| 元素 | 位置 | 行为 |
|---|---|---|
| 自定义导航栏 | 顶部 | 沉浸式，返回 + 标题 + 右侧动作 |
| AI 助手悬浮按钮 | 右下（方案页/菜谱页/结果页）| 点击展开底部抽屉 |
| 忌口速览条 | 首页 | 显示全局忌口，可快捷编辑 |

## 五、页面规范

**目标**：3 秒内让用户理解"这是什么、怎么用"

```

│  ☰                    深圳 ▾  │

│                              │
│  ┌────────────────────────┐  │
│  │   [食物特写大图]         │  │  Hero 占屏 45%
│  │                        │  │
│  │   ┌──────────────────┐ │  │
│  │   │  📷  扫 菜 单    │ │  │  探出按钮
│  │   └──────────────────┘ │  │
│  └────────────────────────┘  │
│                              │
│  ┌──────────┐ ┌──────────┐   │
│  │    🍽    │ │   🧑‍🍳    │   │  次入口
│  │ 拍照识菜 │ │ AI 菜谱  │   │
```

**关键点**：
- Hero 图必须是真实美食摄影（暖色调，有热气/光泽）
- 主 CTA"扫菜单"视觉权重 > 其他所有元素
- 忌口速览条让用户感知"它记得我"

- 识别中用**步骤清单**而非菊花
- 质量检测失败时给具体建议："光线太暗了，换个亮一点的地方"

### P3 菜单结果页

见 PRD §9.4 P2。要点：
- 存疑项**单独分组置底**，不与正常菜品混排
- 顶部"4页/切换"支持多页菜单
- 底部吸底 CTA 常驻

### P4 点单方案页

见 PRD §9.4 P3。要点：
- 顶部预算条显示百分比进度（≤100%），超过时红色 + "为满足预算已调整"
- 菜品按类别分组（荤菜 2 / 素菜 1 / 主食 0）
- 冲突警告**不折叠**
- 「换一道」就地替换，不整页刷新

### P5 约束配置面板

见 PRD §9.4 P4。要点：
- 底部弹起，最大高度 85vh
- 拖拽把手 + 遮罩点击关闭
- 底部按钮上方实时预估文案
- 键盘弹出时面板上推（`adjust-position`）

### P6 AI 助手抽屉

见 PRD §9.4 P5。要点：
- 最高 75vh，背景遮罩 40% 黑
- 顶部显示当前会话上下文摘要
- 约束变更时抽屉顶部插入 `[约束已更新]` 提示条

## 六、交互与动效

### 6.1 动效参数表

| 场景 | 效果 | 时长 | 缓动 |
|---|---|---|---|
| 页面转场 | 横向滑动 | 300ms | ease-out |
| 卡片入场 | translateY(12px)→0 + 淡入 | 300ms | cubic-bezier(.2,.8,.2,1) |
| 列表错峰 | 每项延迟 60ms | — | — |
| 按钮按下 | scale(.97) | 100ms | ease-out |
| 抽屉弹起 | translateY(100%)→0 | 300ms | cubic-bezier(.2,.9,.3,1) |
| 遮罩淡入 | opacity 0→.4 | 250ms | ease |
| 卡片生成 | scale(.96)→1 + 淡入 + 微光 | 400ms | cubic-bezier(.2,.8,.2,1) |
| Chip 选中 | scale 1→1.1→1 | 200ms | ease-out |
| 置信度徽标（处理中）| 呼吸光 | 2s loop | ease-in-out |
| 思考步骤点亮 | 灰→橙→绿 | 300ms | ease |
| 数字变化 | 计数动画 | 500ms | ease-out |

### 6.2 反馈原则

1. **任何点击必有反馈**：按下态、加载态、或内容变化，三者必有其一
2. **耗时 > 1s 必有进度说明**：说明在做什么，而不是转圈
3. **耗时 > 3s 必有可中断**：提供取消，返回不丢状态
4. **失败必须给下一步**：不只说"失败了"，要说"接下来怎么办"

### 6.3 流式渲染注意

- 文本逐 token 追加
- 结构化卡片整块淡入
- **收尾渲染必须 `cancelAnimationFrame` 取消挂起帧**，否则尾帧会覆盖最终样式

## 七、状态设计（完整状态机）

每个数据加载模块必须有完整状态：

| 状态 | 表现 | 操作 |
|---|---|---|
| 空 | 插图 + 说明 + 引导按钮 | 主行动 |
| 加载中 | 步骤清单/骨架屏 | 可取消 |
| 加载成功 | 内容 | — |
| 加载失败 | 图标 + 原因 + 重试 | 重试 / 反馈 |
| 部分成功 | 成功内容 + 失败提示条 | 重试失败项 |

**识别失败的具体化**（不要只说"识别失败"）：

| 真实原因 | 提示文案 | 引导 |
|---|---|---|
| 光线不足 | 照片有点暗，菜品细节看不清 | 换个亮一点的地方重拍 |
| 模糊 | 照片有些模糊 | 手持稳一点，或点按对焦后拍 |
| 非菜单 | 这看起来不是菜单 | 确认要扫菜单吗 / 试试拍照识菜 |
| 识别不到 | 没认出菜品 | 拍近一点 / 手动搜索 |
| 网络 | 网络不太稳定 | 已保存图片，稍后重试 |

## 八、可访问性

| 项 | 要求 |
|---|---|
| 字号下限 | 11px（徽标），正文 ≥ 15px |
| 触摸目标 | ≥ 44 × 44 px |

| 长文本 | 支持换行，不截断关键信息（价格、过敏原）|

## 九、小程序平台适配

### 9.1 布局适配

```css
/* 底部安全区 */
padding-bottom: calc(16rpx + env(safe-area-inset-bottom));

/* 顶部自定义导航栏 */
padding-top: env(safe-area-inset-top);
```

- 沉浸式 Hero 需要 `navigationStyle: "custom"`
- 禁止使用 `vh` 单位（iOS 键盘弹出会跳动），用 `flex: 1` 或 `min-height: 0`

### 9.2 资源与包体

| 项 | 限制 | 策略 |
|---|---|---|
| 主包 | ≤ 2MB | 图标用 iconfont 或 SVG sprite，不内联大图 |
| 单文件 | ≤ 2MB | — |
| 分包 | 按需 | 菜谱页、历史页放分包 |
| 图片格式 | 优先 WebP | JPG 兜底；上传前客户端压缩 |
| 首次渲染 JS | ≤ 200KB | 第三方库按需引入 |

### 9.3 图片处理
- 上传前压缩：长边 ≤ 1600px，JPEG q80（可减少 60% 体积与 40% vision token）
- 拍照使用 `sizeType: ["compressed"]`
- 菜谱大图懒加载 + 渐进式显示

### 9.4 交互限制与规避

| 小程序限制 | 规避方案 |
|---|---|
| 无 `:hover` | 用 `:active` + 触摸反馈 |
| 滚动性能 | 长列表用 `recycle-view` 或分页 |
| `position: fixed` 在部分安卓异常 | 用 `page-meta` 或根节点固定 |
| 输入框聚焦层级 | 用原生 `input`/`textarea`，不用 div 模拟 |
| 无 `localStorage` 同步 API | 用 `wx.setStorageSync` 或云开发数据库 |
